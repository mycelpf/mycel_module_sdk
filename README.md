# mycel_module_sdk

`github.com/mycelpf/mycel_module_sdk` — the **single definition of the seam every
mycel gRPC module is built against**: the plain types a module's logic speaks, the
transport glue that serves it, and the host↔module wire contract. Modules *import* it
(never copy it), which is what stops the per-module definitions from drifting apart.

## Where this sits

Three repos form the module toolchain — grasp all three and you have the whole picture:

| repo | role | one line |
|---|---|---|
| **`mycel_module_sdk`** (this) | the **seam** | the types + transport + wire contract every module is built against |
| [`mycel_app_core_modules`](../mycel_app_core_modules) | the **modules** | concrete implementations, one directory each |
| [`mycel_release`](../mycel_release) | the **pipeline** | builds each module's image and pushes it to ghcr |

## The runtime model in one picture

A mycel module is a **full process** — it owns its own data, clock, and syscalls. The
`mycel_app_core` **host is a pure gRPC client**: it dials the module for `Describe` and
`/m/<token>/*`. There is no host→module capability grant; the module's datastore handle
is its *own*, not something the host injects.

```
mycel_app_core (host, gRPC client)  ──dials──▶  a module (full process)
                                                 └─ serves Describe + /m/<token>/*
```

## The two import surfaces

The core invariant is **logic purity**: the root package imports neither the gRPC
bindings nor any datastore driver, so a module's own logic stays transport-agnostic and
natively testable. Transport lives in a separate package.

```
a module's logic  →  import "…/mycel_module_sdk"          // Request, Response, Row, Host, RouteFunc, Descriptor
its main.go       →  import "…/mycel_module_sdk/server"   // server.Serve(modulesdk.Descriptor{…})
```

## Packages

| package | what it is |
|---|---|
| `.` (`modulesdk`, [sdk.go](sdk.go)) | **pure** types + the `Host` seam. `Request`/`Response`/`Row`/`RouteFunc`/`Descriptor`, and `Host` (the per-request datastore interface). |
| `./server` | transport glue — `server.Serve(Descriptor{…})` adapts gRPC `HandleRequest` to the pure types, implements `Host` over a `*sql.Tx`, adds peer-cred + telemetry. |
| `./analytics` | **stdlib-only** business-event + KPI client: `Emit` (non-blocking), the queue + flusher, and `KPI` reads. Takes its transport as a func value, so it imports neither gRPC nor `./server`. |
| `./contracts/modulerpc/v1` | the host↔module gRPC wire contract (`modulerpc.proto`, `ui_contract.proto`). Generated by `go generate ./contracts/...` with the generators pinned in `contracts/tooling.versions`; `_scripts/check_generated.sh` fails on stale, missing or unexpected generated files. |
| `./wire` | explicit adapters between the pure types and the protobuf contract: `DescribeResponseFromDiscovery`, `DiscoveryFromDescribeResponse` (decode + validate, for app_core), `UserContextFromUser`, `UserFromUserContext`. |
| `./modulerpc/v1` | deprecated aliases of `./contracts/modulerpc/v1`; registers nothing. |

### v0.2 declarations (app_core design v0.2, sdk.md S2, S3, S8, S11)

| Field / API | Meaning |
|---|---|
| `Descriptor.DescriptorSchemaMajor` | 0 legacy, 1 typed. With 1 and `UI == nil` the module has no UI. |
| `Descriptor.UI` (`UIDescriptor`) | kind (`shell`/`own`), element `<token>-app`, entry asset, contract major/minor, browser routes, API/asset prefixes, slots. |
| `Descriptor.NEEDED_MYCEL_LICENSE` | catalog product IDs (`clc`, `helix`), compiled in, reported as `needed_mycel_license`. `ValidateNeededMycelLicense`, `LicenseProductIDs`, `LicenseLabelValue`. |
| `Descriptor.RouteClasses` | IAM route classes for app_core admission. |
| `NavEntry.Group` | per-entry menu group. |
| `Descriptor.VerifyContext` | cancellable startup verification (5 s per attempt). |
| `Descriptor.Start` | runs once after verification, before SERVING, with a `Datastore` and `Background`; waited for at shutdown. |
| `Request.User`, `UserFromContext` | verified user from app_core; never from a header. |
| `ErrorEnvelope`, `ErrorResponseFor`, `DecodeErrorEnvelope` | shared error body `{code, message, traceId}`. |
| `ValidateDiscovery`, `ResolveUI` | boot and host validation; legacy vs typed UI resolution. |
| `RouteClassNetworkService` | provisioned network-service route (login admission matrix): no user context. |
| `Request.Context()` | the gRPC call context; cancelled when app_core gives up on the call. |
| `Request.HeaderFields`, `Response.HeaderFields` (`HeaderField`) | lossless headers (sdk.md S4): repeated values, one Set-Cookie per cookie. The legacy maps stay; a newline-joined `Set-Cookie` in `Response.Headers` is still accepted and split. CR, LF or NUL in a value is refused (400 / 500 `invalid_header`). |
| `ApplyModuleHeaders`, `HostSecurityHeaderNames`, `RemoveHopByHopHeaders` | host side of S4: a module cannot set host security or hop-by-hop headers. |
| `TransportCeilingBytes`, `MaximumBodyBytes`, `MaximumHeaderBytes` | S5 budgets (32 MiB, 30 MiB, 64 KiB): 413 `request_too_large`, 502 `module_response_too_large` (the transaction rolls back). `wire.CheckHandleRequestBudget`, `wire.CheckHandleResponseBudget`. |
| `ValidateOpenAPI`, `FederateOpenAPI` | S6: OpenAPI paths are complete host paths `/m/<token>/…`; duplicate operation IDs, components and foreign prefixes fail. Enforced at boot for typed modules. |
| `contracts/typescript` | `@mycelpf/module-contract`: generated host JSON types (`src/contract.ts`) and `validate()`. Regenerate with `go generate ./contracts/typescriptgeneration`; another repository writes its own copy with `go run github.com/mycelpf/mycel_module_sdk/contracts/typescriptgeneration/command -output <file>`. |

A typed (schema 1) module also refuses to boot when it cannot mark itself non-dumpable (linux), when a host-reserved variable (`MYCEL_HOST_*`) is in its environment, or when it would listen on TCP outside a `mycel_module_development` build.

### Business events (`./analytics`)

A module emits at a business state transition; the client queues in-process and a
background flusher delivers batches to the `mycel_kpi` module over `server.CallExt` (a
direct module→module dial — the host is not involved). `Emit` takes no context and
returns no error, because both would put analytics back in the OLTP path.

```go
an := analytics.New(analytics.Config{Service: "acme", Transport: server.CallExt})
…
an.Emit(analytics.Event{
    Type: "OrderSubmitted", SubjectType: "order", SubjectID: id,
    Attrs: map[string]string{"customer_tier": tier},
    Nums:  map[string]float64{"weight": w},
}.WithRequest(req))   // actor_id from the verified req.User, trace_id from traceparent
```

**Wire `Shutdown`, or every deploy loses events.** `GracefulStop` drains in-flight RPCs
and knows nothing about the queue, so without the hook the process exits with events that
`Emit` already accepted, that no counter recorded, and that no error reported — invisible
in dev, permanent in production:

```go
server.Serve(modulesdk.Descriptor{…, Shutdown: an.Shutdown})
```

Unset `MYCEL_KPI_URL` disables the client entirely (no goroutine, no retries), so an app
running without a kpi module costs nothing.

### The transaction model (the one rule to remember)

`Host` is a Postgres transaction scoped to the module's schema (`search_path = <token>`).
Every `Query`/`Exec` made while serving **one request** runs inside a **single**
transaction — you do *not* begin/commit. The server commits when the handler returns
status `< 500` and rolls back on a `5xx` or any failed statement. Always pass values as
`params`, never concatenate into SQL.

## Consumption

This module is **published publicly** — a module anywhere on disk resolves it the
ordinary way, with no sibling checkout and no workspace layout requirement:

```
require github.com/mycelpf/mycel_module_sdk v0.1.0
```

That is what `mycel init` emits, and it is why a scaffolded module no longer carries a
copy of this SDK inside it. Copies drift; a version does not.

Inside this workspace the six first-party modules additionally pin a `replace` to the
sibling checkout, so a change here is visible to them without a release:

```
replace github.com/mycelpf/mycel_module_sdk => ../../../../mycel_module_sdk
```

(The `../` depth depends on the consumer's location — e.g. a module's `module/service/`.)
A `replace` cannot resolve inside a build container, so the release pipeline runs
`go mod vendor` around those builds; see `mycel_app_core_modules/RELEASE.md`. Consumers
outside the workspace need none of this.

## Who builds against it

The six gRPC modules in [`mycel_app_core_modules`](../mycel_app_core_modules) — `mycel_iam`,
`mycel_cluster_console`, `mycel_file_system`, `mycel_kpi`, `mycel_project_management`,
`mycel_workflow_manager`. (The `mycel_client_workflow` builder base is a Temporal worker,
not a gRPC module, and does not use this SDK.)
